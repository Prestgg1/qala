# Migrations

Migrations are plain SQL files in `database/migrations/`, applied in name order by `qala migrate` (each once, each in
its own transaction). You rarely write them by hand: `qala migrate:make` compares your models with the live database
and writes the SQL for the difference.

```sh
qala migrate:make add_due_dates   # writes database/migrations/0003_add_due_dates.sql
qala migrate                      # applies it
qala migrate:make check --print   # print the SQL instead of writing a file
```

## What it generates

| difference | SQL |
|---|---|
| model without a table | `create table … (columns, primary key)` |
| new field | `alter table … add column …` |
| type changed | `alter column … type … using …` (marked `-- review`) |
| nullability changed | `set not null` / `drop not null` |
| default changed | `set default …` / `drop default` |
| `.unique()` / `.index()` / `.references()` added | constraint / index / foreign key |

Tables are created before any foreign key is added, so models may reference each other in any order.

A new NOT NULL field without a default is added as nullable, with a note to backfill and then run the `set not null`
shown in the file — existing rows would otherwise make the migration fail.

## Nothing is dropped

Columns and tables that exist in the database but not in the models, and foreign keys that point elsewhere, are
written as **comments** at the end of the file:

```sql
-- Not applied automatically (review):
-- tasks.legacy_flag is not in the model; to remove it:
--   alter table "tasks" drop column "legacy_flag";
```

Uncomment what you really want to drop. `qala_migrations` itself is never reported.

## Example

```ts
export const Label = model("labels", {
  id: t.uuid().primary(),
  projectId: t.uuid().references(Project, { onDelete: "cascade" }),
  name: t.string({ max: 40 }).type("varchar(40)"),
  color: t.string().default("gray"),
  createdAt: t.datetime().now(),
});
```

```sql
-- 0004_labels: generated by `qala migrate:make` from the models. Review before applying.

create table "labels" (
  "id" uuid not null default gen_random_uuid(),
  "project_id" uuid not null,
  "name" varchar(40) not null,
  "color" text not null default 'gray',
  "created_at" timestamptz not null default now(),
  primary key ("id")
);

alter table "labels" add constraint "labels_project_id_fkey" foreign key ("project_id") references "projects" ("id") on delete cascade;
```

## Types

| schema | column |
|---|---|
| `t.uuid()` | `uuid` |
| `t.string()`, `t.email()`, `t.enum()`, `t.literal()` | `text` |
| `t.datetime()` | `timestamptz` |
| `t.integer()` | `integer` (identity when it is the primary key) |
| `t.number()` | `double precision` |
| `t.boolean()` | `boolean` |
| `t.unknown()`, `t.array()`, `t.object()` | `jsonb` |

Use `.type("…")` for anything else (`varchar(n)`, `numeric(12,2)`, `bigint`).

## Existing databases

Adopt a database that already exists with `qala db:pull` (models from the schema), then use `migrate:make` from there
on. `migrate:make` reads the `public` schema; only single-column keys, indexes and foreign keys are compared.
